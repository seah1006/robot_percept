# r4 계획서 검토 R4-C (사용자·교육·검증 관점) + R4-O(구현 관점) 합의안

검토 대상: notes/plan_r4_industrial_cobot.md. 동료: R4-X(Codex)는 한도로 불참, R4-O(Claude Opus)가 대체. 왕복 1회(제안 -> K1~K7 회신 -> 수용 확인)로 합의. 읽기 전용 검토이며 코드·서버 실행 없음.

## 0. 총평
계획서는 기술 검증(FK/자코비안 정확도)에는 강하지만 사용자 목표("데이터를 직관적으로 본다", 면접/교수님 시연에서 FK/IK 설명)를 위한 학습 순서·시연 시나리오·UI 합격기준이 없다. 패널 9종 동시 구현은 과하며 MVP를 잘라야 한다.

## 1. 항목별 수정안 (우선순위 P0 > P1 > P2)

### 1.1 화면·학습 흐름 (P0)
- 화면을 "학습 순서"로 재배치: 3D 뷰 + DH 표 + 행렬 패널(MVP) -> IK -> 비교 -> 자코비안.
- **스텝퍼(MVP 포함)**: 관절 1개씩 선택하면 해당 A_i와 누적 T0i가 강조되고, T = A1·A2·…·Ai 곱이 한 단계씩 쌓이는 과정을 보여줌. T 누적은 클라이언트에서 계산(저렴).
- DH 파라미터 θ·d·a·α 각각에 툴팁(의미 + 3D에서 해당 거리/각도 표시).
- **특이점 시각화**는 시연 핵심이라 비교보다 앞(P0~P1): 손목(θ5≈0)·어깨·팔꿈치 경고 + 조작성 수치 + 3D 색 변화. 판정식은 기구학 모듈에서 거의 공짜.
- 과한 항목은 후순위: 자코비안 6x6 히트맵, 작업영역 점구름, CSV/JSON 내보내기, 그래프(P2).
- 패널 숨김 시 갱신 중지(계획서 유지).

### 1.2 시연 프리셋 (P0)
교수님 앞 3분 데모용, JSON 고정 + pytest 수치 회귀:
1. 홈 자세: DH 표·행렬 읽는 법 (스텝퍼로 A_i 곱 설명)
2. 손목 특이점 θ5 -> 0: 조작성 하락, 경고
3. 팔 완전 신장(어깨/팔꿈치 특이점): 작업 영역 경계
4. 같은 목표 두 로봇 IK 비교(해 개수, 조작성, 관절 여유)
각 프리셋에 한 줄 설명 문구와 "무엇을 봐야 하나" 안내.

### 1.3 산업용 vs 협동 비교 지표 (P1)
- 의미 있는 지표: 작업영역 단면(오프라인 사전계산 JSON), 조작성 분포 히스토그램(무작위 N자세, 오프라인), 같은 목표 IK 해 수·조작성, 카탈로그 J6 속도비(420 : 180°/s).
- **같은 직선 경로 소요시간은 v2로 미룸**: J1~J5 속도가 카탈로그에 없어 숫자가 사실처럼 보일 위험. 하려면 "가정값" 크게 표기.
- **정직성 표기 규칙**: 값마다 출처 배지 3종 - `카탈로그 p.NN`(사실), `치수표 해석`(기호 해석, 추정 포함), `가정값`(질량·관성·J1~J5 한계/속도; 다른 색 + "카탈로그 미기재"). 비교표에서 가정값은 회색 이탤릭. 질량은 본체 무게(카탈로그)와 링크 질량(가정)을 혼동하지 않도록 분리.
- "공정 비교(12kg 동일)" 문구는 유지하되, 작업 반경이 다르므로(1420 vs 1324) 같은 조건이 아님을 명시.
- 협동 속도/힘 제한 표시는 "설명용, 안전 인증 아님" 유지, 카탈로그에 없는 한계값은 만들어 표시하지 않음.

### 1.4 합격 기준 보강 (P0)
추가 UI 사용성 항목:
- 슬라이더/IK 입력 -> 행렬 갱신 체감 지연 p95 ≤100ms (브라우저 측정; POST 왕복 기준). 함수 호출 시간과 HTTP 왕복 시간을 따로 보고.
- 렌더 fps는 서버 MJPEG 대신 브라우저 rAF 기준 30초 창 ≥29.7(구조 변경 반영, 1.5 참조).
- 1280x720 스크린샷 체크리스트: 3D 뷰·DH 표·행렬이 스크롤 없이 한 화면, 변하는 칸 강조 보임, '근사 모델, 공식 CAD 아님' 문구 상시 노출, 가정값 배지 보임.
- 프리셋 4개 재현(수치 회귀 + 스크린샷), 스텝퍼가 1~6번째 관절 순서대로 T를 누적하는지 확인.
- 비개발자 초보 확인: 사용자 본인이 DH 표를 보고 3분 설명 가능한지 리허설(사용자 판단 항목, PASS 근거 아님).

### 1.5 구조 (R4-O 제안 채택, P0)
- arm_worker(MuJoCo 오프스크린+JPEG 30fps) 폐기. Flask 프로세스 내 `ArmRuntime`(numpy DH, FK+J 수십 µs). MuJoCo는 mj_kinematics 검증용으로만 로드. 렌더·좌표축·라벨은 브라우저 three.js.
- FK/IK는 POST 응답으로 즉시 반환, 푸시 필요 시 `/status/ws`에 'arm' 빌더 추가(10Hz). 페이로드 약 2.1KB, 15Hz에서 부하 1% 미만(R4-O 실측). 집 AMD PC도 서버 GL 의존 없음.
- 공유 파일 목록 정정: 로봇 선택 select(#h-mode)는 `web/static/humanoid.js`(onchange가 g1 외 전부 panda 처리 -> 수정 필수, P1c S 페어 소유), `web/realtime.py`(register_realtime 시그니처). S 페어와 수정 순서 합의 필요.

### 1.6 모델·치수 검증 (R4-O 제안 채택, P0)
- YMX: A~E 해석 강하게 지지(H=A+C+√(D²+E²), G=H−A 등 다수 모델에서 일치). 단 1420은 **손목중심 기준**이며 플랜지 기준이면 약 1533(+8%): 합격기준에 기준점 명시.
- YBL: D=d5(일직선) 확정(G=B+C+D 4모델 일치). **E·F 중 어느 것이 d4/d6인지 치수표만으로 결정 불가** -> 대안 2개(F=d4·E=d6 / E=d4·F=d6)를 문서화하고 '추정' 표기. 계획서의 "치수 검증" 행에 이 불확실성 반영.
- "근사 모델 최대 반경 ±0.5%"는 같은 치수로 만든 모델이라 동어반복 -> FK 몬테카를로로 작업영역 치수(YMX I·J·L, YBL H·K)를 재현하는 검증으로 교체. YMX/YBL의 1µm FK 일치도 "생성기 일관성 검사"라고 명시(실제 제품 정확도 아님).
- UR5e: Menagerie MJCF는 공개 DH와 최대 0.7mm 차이 -> "공개 DH vs MuJoCo ≤1µm"은 FAIL. MJCF에서 추출한 DH로 1µm(float64이면 여유) 보고, 공개 DH와의 차이는 별도 ≤1mm로 보고.

### 1.7 IK·특이점 기준 (P1)
- 해석해(UR형 8해, 구형손목 8해) 우선, 수치 DLS는 보조. 목표는 무작위 q의 FK로 생성(도달 보장). 성공 = 위치 ≤0.1mm, 자세 ≤1e-3rad. 해석해 100%, 수치해 ≥98%. p95는 함수 호출/HTTP 왕복 별도 보고(33ms는 느슨해 폐기 가능).
- humanoid_ik.ArmIK는 G1 전용이라 재사용 불가, DLS 공식만 차용.
- 추가 테스트: 8해 전부 FK 역검증, 현재 q 최근접·한계 내 해 선택, 직선 경로 100스텝 분기 점프 없음, 관절한계 위반 0, 단순 자기충돌·바닥은 회피 아닌 경고만.
- 특이점 오경고 기준은 σmin(정규화 J) 또는 해석 det 인수로 정의, ε1/ε2 히스테리시스 밴드 사용.

### 1.8 법적·표기·공개 저장소 (P0)
- "YUIL/유일로보틱스/LINKOBOT/YMX/YBL" 상표는 제품 식별 목적 사용만, README·화면에 "비제휴·비공식, 상표는 각 소유자 소유" 문구.
- 카탈로그 PDF·로고·카탈로그 그림 저장소 제외(현행 유지), 수치는 사실값 최소 인용 + 출처(카탈로그 쪽번호, URL) 유지. notes/yuil_specs.md가 공개 저장소에 올라가므로 표 전체 전재가 부담되면 사용하는 2모델 행 중심으로 축약 검토.
- 화면·README에 "카탈로그 치수 기반 근사 모델(공식 CAD 아님), 실제 제품 성능/안전 보증 아님" 상시 표기. 외형은 단순 도형(현행).
- STEP 문의(확인사항 4)는 허락 받기 전 외형 사용 금지.

### 1.10 누락 위험 (추가)
- 치수 기호 해석 대안 동시 존재(YBL E/F) -> 사용자에게 "추정"을 숨기지 말 것.
- 파일 충돌: humanoid.js/realtime.py (위 1.5).
- 과도한 범위로 시연 전 미완성: MVP를 끊어서 단계마다 시연 가능 상태 유지.
- 설명 정확성: 사용자가 면접에서 "공식 모델"로 오해 발언하지 않도록 README에 "면접 설명용 한 줄" 포함.
- 5080 사용자 서버 금지/측정 락 규칙은 TEAM_R3 그대로.
- 계획서의 미결정 항목: 로봇 조합·UR5e 메뉴 노출·병행 여부. 제안: 조합 유지, UR5e는 테스트 전용(메뉴 비노출, 노출하면 '검증용 참조' 표기), r3 마무리와 병행하되 humanoid.js 수정은 S 페어 이후.

## 2. 남은 이견
- 없음(R4-O와 합의). 사소한 차이: 경로 소요시간은 R4-C가 "가정 표기 시 포함 가능"으로 열어뒀으나 R4-O의 v2 안으로 합의. 사용자 결정 필요: 확인사항 1~4(1.10 제안 포함), 그리고 스텝퍼를 MVP에 넣는 범위 확정.
